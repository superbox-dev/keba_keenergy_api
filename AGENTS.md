# AGENTS.md

Async Python client (`aiohttp`) for the KEBA KeEnergy Web HMI API (heat pump controllers).
Published on PyPI and used by the Home Assistant integration, so the public API must stay backwards compatible.

## Setup and commands

The project uses `uv`. Always run tools through `uv run`.

```bash
./scripts/setup.sh          # uv sync --locked --dev + prek hooks
uv run pytest               # tests (parallel, coverage, stops at first failure)
uv run ruff format          # format
uv run ruff check --fix     # lint (select = ALL)
uv run ty check             # type check (warnings are errors)
uv run rumdl check --fix    # Markdown lint
uv run yamllint .           # YAML lint
./scripts/lint.sh           # all linters at once
uv run mkdocs build --strict  # build the docs
```

Before you finish a change, run `./scripts/lint.sh` and `uv run pytest`. CI runs both on Python 3.11–3.14.

## Hard rules

- **100% test coverage is enforced** (`fail_under = 100`). Every new code path needs a test.
- **Python 3.11 is the minimum.** Do not use syntax or stdlib features from newer versions
  (e.g. no `type` statements, no PEP 695 generics, no `typing.Self`/`override` without a fallback).
- **Line length 120**, single-line imports (`force-single-line`), full type annotations.
- **Docstrings use NumPy style** (rendered by mkdocstrings). Tests are exempt from docstring rules.
- Prefer fixing a lint error over adding `# noqa`. If a `noqa` is needed, use the specific rule code.
- Never edit `keba_keenergy_api/version.py`. It is generated by `setuptools-scm`.
- Don't rename or remove public methods or constants. If a rename is needed, keep the old name as an alias
  (see `SolarCircuitPriority1Before2StringEndpoint.helper`) and note it in the changelog.

## Architecture

- `keba_keenergy_api/constants.py`: Endpoint definitions. Each section (`System`, `HeatPump`, `HeatCircuit`, ...)
  is an `Enum` whose members are `FloatEndpoint` / `IntegerEndpoint` / `StringEndpoint` instances that hold the
  controller variable path (`%s` = zero-based device index) and optional `human_readable` enum, `quantity`, etc.
- `keba_keenergy_api/endpoints.py`: `BaseEndpoints` (payload generation, POST to `/var/readWriteVars`, value
  conversion) and one `*Endpoints` class per section with the public `get_*` / `set_*` methods.
- `keba_keenergy_api/api.py`: `KebaKeEnergyAPI`, the entry point. Exposes the section clients
  (`client.system`, `client.heat_pump`, ...) and the bulk methods `read_data`, `read_message_ids`, `write_data`.
- `keba_keenergy_api/error.py`: exceptions (`APIError`, ...).

Endpoint conventions:

- A path containing `.param.` is writable. Everything else is read-only (derived automatically).
- Every sensor path ending in `.values.actValue` **must** set `has_message_id=True`.
  `tests/test_constants.py` enforces this.
- Getters use the `_read_float` / `_read_int` / `_read_str` / `_read_int_or_str` helpers. Enum values accept
  `human_readable: bool = True` (keyword-only). Setters parse enums with `_parse_enum_value`.
- Setter docstrings carry the flash-memory write warning (copy it from an existing setter).

## Adding or changing an endpoint

1. Add the endpoint to the section enum in `constants.py` (plus a `BaseEnum` subclass if it has named values).
2. Add the `get_*` / `set_*` method to the matching `*Endpoints` class in `endpoints.py` with a NumPy docstring.
3. Add happy-path tests (and unhappy-path tests for setters/invalid input) in
   `tests/test_endpoints/test_<section>_section.py`. Mock HTTP with `aioresponses` and assert the exact request
   payload with `assert_called_once_with`. Follow the existing test structure.
4. If you add a new section, also add a page under `docs/keba-keenergy/api/endpoints/`, register it in the
   `mkdocs.yml` nav, and add the client attribute to the mkdocstrings `filters`.
5. Add an entry under `## [Unreleased]` in `CHANGELOG.md`.

## Changelog and git

- `CHANGELOG.md` follows Keep a Changelog (`Added` / `Changed` / `Fixed` / `Security` ...). Write in past tense
  ("Added ...", "Fixed ..."), wrap identifiers in backticks, and link issues as `([Issue #67][issue-67])`.
  Every user-visible change needs an entry. Internal refactors that don't change behaviour don't.
- Development happens on `develop`. `main` is the release branch. Releases are created from `v*` tags
  (`vX.Y.ZbN` = pre-release) and published to PyPI by CI.
- Only commit or push when asked. Don't update `coverage-badge.svg` by hand, CI regenerates and commits it.
